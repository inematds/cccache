What you'll understand here

The Claude API is stateless: with every message, the entire conversation (tools + system prompt + history) is sent again. The prompt caching keeps that already-processed beginning and reuses it—instead of reprocessing everything from scratch every turn. It’s a prefix matching: the cache key is the exact bytes up to a cutoff point; a single different byte in the middle invalidates everything after it.

📖

The terms, made simple

Hit, miss, write, TTL, breakpoint, cache_read_input_tokens — each one defined at its first appearance.

🔧

What breaks the cache

Change the list of tools, dates in the system prompt, nondeterministic order — the silent invalidators and how to find them.

💸

The real savings

Read ~0.1× · write ~1.25× · uncached 1×. When the cache pays off, and when compacting is more worthwhile.
