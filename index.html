🧠 cccache — Prompt Caching no Claude Code

Entenda de verdade o cache que roda por baixo quando você conversa com o Claude Code — o que reaproveita, o que quebra, e como pagar 10% em vez de 100% pelo contexto.

O que você vai entender aqui

A API do Claude é stateless: a cada mensagem, a conversa inteira (ferramentas + prompt de sistema + histórico) é reenviada. O prompt caching guarda esse começo já processado e o reaproveita — em vez de reprocessar tudo do zero a cada turno. É um casamento de prefixo: a chave do cache são os bytes exatos até um ponto de corte; um único byte diferente no meio invalida tudo dali pra frente.

📖

Os termos, sem mistério

Hit, miss, write, TTL, breakpoint, cache_read_input_tokens — cada um definido na 1ª aparição.

🔧

O que quebra o cache

Mudar a lista de tools, datas no system, ordem não-determinística — os silent invalidators e como achá-los.

💸

A economia real

Read ~0,1× · write ~1,25× · não-cacheado 1×. Quando o cache paga, e quando compactar vale mais.
